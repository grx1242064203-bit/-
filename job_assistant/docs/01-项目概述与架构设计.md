# 01. 项目概述与架构设计

## 1. 产品定位

**招聘情报助手**是一款面向求职者的 SaaS 产品，核心价值是"用 AI 替你每天筛岗位"。

```
每日自动采集岗位 → 基于用户自定义画像评分 → 写入用户飞书多维表格 → 微信推送日报
```

### 1.1 目标用户

- 不限行业：金融、互联网、快消、咨询、制造业等全行业通用
- 不限阶段：应届校招、管培生、社招跳槽、实习全覆盖
- 核心诉求：节省每天刷招聘网站的时间，只看"与我相关"的岗位

### 1.2 商业模式

| 档位 | 价格 | 服务内容 |
|------|------|---------|
| 体验版 | 9.9 元 | 3 天日报推送 |
| 秋招版 | 199 元 | 9-11 月每日推送 |
| 春招版 | 149 元 | 2-4 月每日推送 |
| 全年版 | 399 元 | 全年每日推送 |

获客渠道：小红书内容营销 → 付费购买 → 用户安装飞书应用 → 绑定微信推送。

### 2.2 核心流程

#### 流程 A：用户 Onboarding（首次安装）

```
用户安装飞书应用
       │
       ▼
飞书推送 app_open 事件 → 回调服务 /feishu/callback
       │
       ▼
handle_feishu_callback()
  ├─ 提取 tenant_key + open_id
  ├─ 生成 user_id = "{tenant_key}_{open_id}"
  └─ 启动后台线程执行 onboard_user()
       │
       ▼
onboard_user() [加全局锁防并发]
  ├─ 双重检查用户是否已存在
  ├─ setup_user_feishu()
  │   ├─ create_bitable("招聘情报库") → base_token
  │   ├─ resolve_app_token() → 防御 wiki node_token
  │   ├─ verify_bitable_access() → 验证 token 有效
  │   ├─ create_table("岗位数据库") + 批量创建字段
  │   ├─ create_table("已关闭岗位") + 批量创建字段
  │   └─ transfer_owner() → 所有权转给用户
  └─ store.upsert(user) → 写入 users.json
```

#### 流程 B：每日任务执行

```
cron 触发 main.py daily
       │
       ▼
run_daily_all()
  ├─ store.list_active() → 获取未过期用户
  └─ 遍历每个用户:
       │
       ▼
     DailyRunner(user).run()
       ├─ 1. collector.collect() → 搜索 + 抓取 JD
       ├─ 2. score_job() → 基于画像评分
       ├─ 3. _dedupe_and_write() → 去重后写入主表
       ├─ 4. _recheck_and_archive() → 复查在招岗位,关闭的归档
       ├─ 5. _create_daily_report() → 生成飞书日报文档
       └─ 6. wxpusher.send_daily_summary() → 微信推送
```

### 2.3 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 语言 | Python 3.10+ | 生产环境实际运行 3.8，需注意语法兼容性 |
| Web 服务 | http.server (标准库) | 回调服务，无需额外依赖；生产用 Nginx 反代 |
| HTTP 客户端 | requests | 调用飞书 / WxPusher / 搜索 API |
| HTML 解析 | beautifulsoup4 | JD 页面正文提取 |
| 数据存储 | JSON 文件 | MVP 阶段，用户量小；后期迁移 DB |
| 进程管理 | systemd | job-callback 服务 |
| 反向代理 | Nginx | HTTPS 终结 + 反向代理到 :8080 |
| 定时任务 | cron | 每日 9:00 触发 main.py daily |
