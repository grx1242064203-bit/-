# 01 - 项目概述与架构设计

## 1. 产品定位

**校招情报助手**是一个面向应届毕业生的校招岗位智能匹配与推送系统。

- **服务对象**：应届毕业生（秋招/春招/管培/实习）
- **核心价值**：从海量招聘公告中自动提取具体岗位，基于用户画像精准匹配，每日推送
- **交付形式**：飞书多维表格（每人专属）+ 日报文档 + 交互卡片 + 微信推送

## 2. 系统架构总览

系统分为两大子系统：**数据流水线**（中心化采集+分析）和 **用户分发**（每日匹配+推送）。

## 3. 核心架构决策

### 3.1 三表分离：companies / announcements / jobs

**问题**：原始招聘链接和拆分出的具体岗位是不同实体，混在一张表导致统计口径混乱（"总岗位数"既包含链接又包含岗位）。

**方案**：

| 表 | 实体 | 说明 |
|----|------|------|
| `companies` | 公司 | 行业/类型/地点等元数据，每条公司一行 |
| `announcements` | 招聘链接 | 原始公告链接 + 抓取状态 + 分析状态，后台中间表 |
| `jobs` | 具体岗位 | LLM 拆分出的具体岗位，25+ 匹配维度，**给用户的最终数据** |

**关联方式**：通过 `company` 文本字段关联（无外键约束）。

### 3.2 两阶段流水线：抓取与分析解耦

**问题**：串行处理（抓取→分析）时，抓取慢（Playwright 2-5s/条）和分析贵（LLM 3-5s/条）互相等待，总耗时 = 抓取时间 + 分析时间。

**方案**：
- **阶段一** `fetch_announcements.py`：5 线程并发 Playwright 抓取，结果写入 `fetch_results.jsonl`
- **阶段二** `analyze_daemon.py`：tail -f 模式持续消费 JSONL，调用 LLM 分析

**优势**：
- 抓取和分析并行，总耗时 = max(抓取, 分析)
- 中间结果 JSONL 支持断点续传
- 两阶段可独立重试（抓取失败重试抓取，分析失败重试分析）

### 3.3 JSONL 中间结果的并发安全

- 阶段一只用 `"a"`（append）模式写 JSONL，单行原子写入
- 阶段二只读 JSONL，不修改
- 避免了两个进程同时读写同一文件的竞态条件

### 3.4 中心化采集 + 按需分发

- 采集一次（飞书表 → announcements → jobs），所有用户共享 jobs 表
- 每个用户每日从 jobs 表匹配岗位，不重复抓取
- 优势：避免 N 个用户重复抓取同一公告，节省 LLM 成本

### 3.5 规则预筛 + AI 评分

- **规则预筛**：基于结构化字段（job_category/hard_skills/major_required 等）快速过滤 70% 不相关岗位
- **AI 评分**：只对预筛通过的候选集调用 LLM，节省成本
- **每公司限 5**：避免单一公司刷屏，保证岗位多样性

## 4. 数据流详细说明

### 4.1 数据流水线

```
飞书秋招汇总表
    │  (公司名/岗位大类/公告链接/招聘类型/届数/行业/企业性质)
    ▼
feishu_source.py
    ├─ 过滤:只保留校招类型(秋招/秋招提前批/春招/春招补招/春招补录)
    ├─ 归一化:行业 259→18 类,企业性质 19→5 类
    ├─ 解析:届数范围("26届-27届" → min=2026, max=2027)
    └─ 写入:announcements 表 + companies 表
    │
    ▼
fetch_announcements.py
    ├─ 从 announcements 表取 detail_analyzed=0 AND link_valid=1 的记录
    ├─ Playwright 抓取公告正文 + 图片URL(微信链接用 UA 伪装绕过反爬)
    ├─ 图片最多 4 张,压缩到 600px
    └─ 写入 fetch_results.jsonl(status: ok/blocked/fetch_failed/link_invalid)
    │
    ▼
analyze_daemon.py
    ├─ tail -f 读取 JSONL 新行
    ├─ 正文<50 字时用 DeepSeek-VL OCR 图片
    ├─ DeepSeek 拆分具体岗位(25+ 维度)
    │   ├─ 岗位分类: job_category/job_subcategory
    │   ├─ 技能: hard_skills/soft_skills/certifications/languages
    │   ├─ 专业: major_required/major_category
    │   ├─ 学历: min_education/education_preference
    │   ├─ 地点: city/province/is_remote
    │   └─ 职业发展: career_track/career_level/travel_frequency/overtime_level
    ├─ 每个岗位 insert 到 jobs 表
    └─ 更新 announcements.detail_analyzed=1 + analysis_status
```

### 4.2 用户每日任务

```
main.py daily
    │
    ├─ run_sync_and_analyze()  ← 先执行中心化数据同步
    │
    ├─ 遍历活跃用户
    │   │
    │   ├─ UserRunLock (用户级文件锁,防止并发)
    │   │
    │   ├─ user_matcher.match_jobs_for_user(profile)
    │   │   ├─ get_jobs_by_grade(graduation_year)  ← 按届数过滤
    │   │   ├─ _rule_filter()  ← 规则预筛(8 个维度)
    │   │   ├─ _score_and_rank()  ← AI 评分
    │   │   ├─ 过滤评分 < 30
    │   │   └─ _limit_per_company(max=5)
    │   │
    │   ├─ 分离管培岗位 → 写入管培项目表
    │   │
    │   ├─ _dedupe_and_write()  ← 去重后写入飞书主表
    │   │   ├─ 检查飞书表已有 hash
    │   │   ├─ 检查本地 hash_store
    │   │   └─ batch_create_records + hash_store.add()
    │   │
    │   ├─ _recheck_and_archive()  ← 复查在招状态,归档已关闭
    │   │
    │   ├─ _create_daily_report()  ← 生成飞书日报文档
    │   │
    │   ├─ 飞书交互卡片推送(TOP3 + 直达链接)
    │   │
    │   ├─ 微信推送(WxPusher,可选)
    │   │
    │   ├─ 校招截止提醒(3天内)
    │   │
    │   └─ 投递跟踪(已投递岗位关闭通知)
    │
    └─ 失败告警 → 管理员微信
```

## 5. 模块职责边界

| 模块 | 职责 | 不做什么 |
|------|------|---------|
| `feishu_source.py` | 飞书表同步 → announcements/companies 表 | 不抓取公告正文 |
| `fetch_announcements.py` | Playwright 抓取公告 → JSONL | 不调用 LLM |
| `analyze_daemon.py` | 消费 JSONL → LLM 拆分 → jobs 表 | 不抓取 |
| `user_matcher.py` | 从 jobs 表匹配用户岗位 | 不写飞书 |
| `daily_runner.py` | 写飞书 + 日报 + 推送 | 不采集岗位 |
| `scorer.py` | 单岗位评分 | 不查数据库 |
| `onboarding.py` | 新用户建表+转所有权 | 不处理每日任务 |
