# 01. 项目概述与架构设计

## 1. 产品定位

**招聘情报助手**是一款面向求职者的 SaaS 产品，核心价值是"用 AI 替你每天筛岗位"。

```
每日自动采集岗位 → 基于用户自定义画像评分 → 写入用户飞书多维表格 → 飞书推送日报
```

### 1.1 目标用户

- 不限行业：金融、互联网、快消、咨询、制造业等全行业通用
- 求职角色：**校招（应届）** 和 **社招** 两条线（实习功能已下线）
- 核心诉求：节省每天刷招聘网站的时间，只看"与我相关"的岗位

### 1.2 商业模式

| 档位 | 价格 | 服务内容 |
|------|------|---------|
| 体验版 | 9.9 元 | 3 天日报推送 |
| 秋招版 | 199 元 | 9-11 月每日推送 |
| 春招版 | 149 元 | 2-4 月每日推送 |
| 全年版 | 399 元 | 全年每日推送 |

获客渠道：小红书内容营销 → 付费购买 → 用户安装飞书应用 → 自助配置求职偏好。

## 2. 系统架构

### 2.1 整体架构图

**核心设计原则：中心化采集 → 总数据库 → 用户按需分发。**

校招岗位由系统统一采集一次（`company_crawler.py` → `job_db.py`），所有校招用户共享同一份岗位源，按各自画像规则预筛 + AI 评分后分发。社招用户保持原有独立搜索逻辑。

### 2.2 核心流程

#### 流程 A：用户 Onboarding（首次安装）

```
用户安装飞书应用
       │
       ▼
飞书推送 app_open 事件 → 回调服务 /feishu/callback
       │
       ▼
handle_feishu_callback()
  ├─ 提取 tenant_key + open_id
  ├─ 生成 user_id = "{tenant_key}_{open_id}"
  └─ 启动后台线程执行 onboard_user()
       │
       ▼
onboard_user() [加全局锁防并发]
  ├─ 双重检查用户是否已存在
  ├─ setup_user_feishu()
  │   ├─ create_bitable("招聘情报库") → base_token
  │   ├─ resolve_app_token() → 防御 wiki node_token
  │   ├─ verify_bitable_access() → 验证 token 有效
  │   ├─ create_table("岗位数据库") + 批量创建字段
  │   ├─ create_table("已关闭岗位") + 批量创建字段
  │   ├─ 校招用户: create_table("管培生项目") + 批量创建字段
  │   └─ transfer_owner() → 所有权转给用户
  └─ store.upsert(user) → 写入 users.json
```

#### 流程 B：校招总数据库采集（中心化，每日）

```
cron 触发 company_crawler.run_daily_crawl()  (首次用 run_initial_crawl)
       │
       ▼
CompanyCrawler.crawl()
  ├─ 筛选公司: 首次全量 / 之后只扫 has_2027_announcement=False 的公司
  ├─ 对每家公司构建查询: 官网域名 site: + 公众号 site:mp.weixin.qq.com
  ├─ Tavily 搜索 → 来源白名单过滤(排除领英/Boss等第三方)
  ├─ fetch_jd_by_source() 抓取 JD 正文
  ├─ LLM.verify_campus_announcement() → 校验是否有效 2027 届校招
  ├─ LLM.generate_jd_summary() → 生成 JD 摘要
  └─ job_db.insert_job() → 入库(去重 hash 唯一约束)
```

#### 流程 C：每日任务执行（用户分发）

```
cron 触发 main.py daily
       │
       ▼
run_daily_all()
  ├─ store.list_active() → 获取未过期用户
  └─ 遍历每个用户:
       │
       ▼
     DailyRunner(user).run() [用户级文件锁防并发]
       ├─ _ensure_table_fields() → 自动补建缺失字段(如 行业/公司类型/难度)
       │
       ├─ 校招用户(role=campus):
       │    └─ match_jobs_for_user() → 从总数据库匹配
       │         ├─ 规则预筛(行业/公司类型/专业关键词) → 过滤 ~70%
       │         ├─ AI 评分(score_job) → 相关性/难度/推荐度/简评
       │         └─ 每公司最多 5 条
       │
       ├─ 社招用户(role=social):
       │    └─ collector.collect() → 独立搜索 + AI 质量筛选 + score_job
       │
       ├─ 管培岗位 → 写入独立"管培生项目"表
       ├─ 普通岗位 → _dedupe_and_write() → 去重后写入主表
       ├─ _recheck_and_archive() → 复查在招岗位,关闭的归档
       ├─ _create_daily_report() → 生成飞书日报文档
       ├─ _send_daily_card() → 飞书交互卡片推送(主渠道)
       ├─ _check_deadline_reminders() → 截止前 3 天提醒
       └─ _check_applied_jobs() → 投递跟踪
```

### 2.3 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 语言 | Python 3.10+ | 生产环境实际运行 3.8，需注意语法兼容性 |
| Web 服务 | http.server (标准库) | 回调服务，无需额外依赖；生产用 Nginx 反代 |
| HTTP 客户端 | requests | 调用飞书 / WxPusher / 搜索 API / LLM |
| HTML 解析 | beautifulsoup4 | JD 页面正文提取 |
| LLM | DeepSeek (兼容 OpenAI 格式) | 简历解析、JD 摘要、校招公告检视、关键词优化 |
| 数据存储 | JSON 文件 + SQLite | 用户配置用 JSON；校招总数据库用 SQLite |
| 进程管理 | systemd | job-callback 服务 |
| 反向代理 | Nginx | HTTPS 终结 + 反向代理到 :8080 |
| 定时任务 | cron | 每日 9:00 触发 main.py daily；每周一 9:30 热度榜 |
