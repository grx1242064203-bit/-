# 02. 核心模块与数据模型

## 1. 模块总览

```
job_assistant/
├── config.py            # 全局配置（环境变量注入）
├── models.py            # 数据模型 + JSON 存储（UserStore / HashStore）

├── job_db.py            # 校招总数据库（SQLite，只存 2027 届校招岗位）
├── user_matcher.py      # 校招用户匹配器（规则预筛 + AI 评分 + 每公司≤5）

├── wxpusher_client.py   # WxPusher 微信推送（可选辅助通道）

├── weekly_rankings.py   # 每周校招投递热度榜
├── main.py              # 多用户调度入口
├── callback_server.py   # 飞书事件回调 HTTP 服务
├── bind_wxpusher.py     # 用户微信绑定脚本
├── verify_fix.py        # 生产环境验证脚本
└── data/                # 用户数据（自动创建）
    ├── users.json
    ├── hashes/{user_id}.json
    └── jobs.db          # 校招总数据库（SQLite）
```

## 2. 模块详解

### 2.1 config.py — 全局配置

**职责**：从环境变量读取所有配置，不硬编码任何敏感信息。

```python
@dataclass
class Settings:
    FEISHU_APP_ID / FEISHU_APP_SECRET    # 飞书应用凭证
    FEISHU_ENCRYPT_KEY / VERIFICATION_TOKEN  # 事件订阅校验
    WXPUSHER_APP_TOKEN                   # WxPusher 应用 Token
    DATA_DIR                             # 数据存储目录
    DAILY_JOBS_PER_USER (默认 20)        # 每用户每日采集上限
    FEISHU_RETRY (默认 3)                # 飞书 API 重试次数
    FEISHU_API_INTERVAL (默认 0.2s)      # 飞书 API 调用间隔
    JOB_BOARD_DOMAINS                    # 通用招聘网站域名
```

**设计原则**：
- 所有配置项有默认值，缺失时不崩溃
- `DAILY_JOBS_PER_USER` 等运行参数可通过环境变量调整，无需改代码

### 2.2 models.py — 数据模型与存储

**核心类**：

#### UserProfile（用户画像）
```
role: str                  # 求职角色: campus(校招) / social(社招) —— internship 已下线
school, degree, major      # 学校、学历、专业
experience_years: int      # 工作年限（社招用户使用）
core_skills: List[str]     # 核心技能
direction_keywords: Dict[str, List[str]]   # 目标方向 → 关键词列表
target_companies / target_industries / target_cities: List[str]
target_certificates: List[str]

# 校招偏好（role=campus 时生效）
campus_company_types: List[str]      # 偏好公司类型: 国央企/民企/外企
campus_difficulty: str               # 可接受难度: 激烈/普通/轻松
campus_prefers_management: bool      # 是否偏好管培项目
resume_text: str                     # 原始简历文本（留档，供 LLM 解析）
```

> **简化说明**：校招用户默认 = 2027 届，已移除 `graduation_year` / `graduation_date` 字段；`role` 只保留 `campus` / `social`，移除 `internship`。

#### User（用户）
```
id = "{tenant_key}_{open_id}"
feishu_tenant_key / feishu_open_id
feishu_base_token / feishu_table_id / feishu_closed_table_id
wxpusher_uid
profile: UserProfile
plan: trial / autumn / spring / yearly
expire_date: YYYY-MM-DD
created_at / last_run_at
```

#### UserStore（用户存储）
- 存储路径：`{DATA_DIR}/users.json`
- **并发安全**：`fcntl.flock` 排他文件锁 + 原子写入（`os.replace`）
- **防 lost-update**：`upsert` 时持锁 → `_reload_from_disk` → 修改 → `_save`

**⚠️ 已知限制**：`_reload_from_disk` 只加载内存中不存在的用户。若多进程同时修改**不同**用户，后保存的进程会覆盖先保存进程对其他用户的修改。MVP 单进程场景无问题，多进程部署需重构为全量合并或迁移 DB。

#### HashStore（去重哈希）
- 存储路径：`{DATA_DIR}/hashes/{user_id}.json`
- 记录已见过的岗位 hash，避免重复写入
- **⚠️ 已知缺陷**：`add()` 方法无文件锁，并发写入可能损坏 hash 文件

### 2.3 schema.py — 多维表格字段定义

**单一事实来源**：建表和写记录都引用 `JOB_FIELDS`，避免字段不一致。

`JOB_FIELDS` 包含 22+ 字段，核心字段：
| 字段 | 类型 | 说明 |
|------|------|------|
| 岗位标题 / 公司 / 部门 / 地点 | text | 基础信息 |
| 薪资范围 / 经验要求 / 学历要求 | text | 匹配维度 |
| **行业 / 公司类型 / 申请难度** | text | 校招总库透传字段 |
| JD摘要 / JD链接 | text / url | 详情 |
| 抓取日期 / **发布时间** | datetime / text | 时间 |
| 投递截止日期 | datetime | 校招截止提醒（截止前 3 天） |
| 岗位类别 / 平台层级 | text | 分类 |
| 相关性评分 / 难度评分 | number | 评分 |
| 综合推荐度 | select | 优先申请/可申请/观望/跳过 |
| 简评 / 申请建议 | text | AI 输出 |
| 申请状态 | select | 未投递/已投递/面试中/Offer/拒绝 |
| 去重hash | text | 去重标识 |
| 应届窗口 / 是否在招 | select | 状态标识 |

`CLOSED_JOB_FIELDS` = `JOB_FIELDS` + 关闭日期字段。
`MANAGEMENT_FIELDS` = 管培生项目表专用字段子集。

> **字段自动迁移**：`daily_runner._ensure_table_fields()` 会自动为存量用户补建缺失字段（如行业/公司类型/难度），无需手动迁移。

### 2.4 feishu_client.py — 飞书 API 客户端

**核心能力**：

1. **Token 管理**：`tenant_access_token` 缓存，2 小时过期，提前 5 分钟刷新
2. **重试机制**：指数退避，应对限流（code=99991400）和临时错误
3. **Wiki token 解析**：`resolve_app_token()` 将 wiki node_token 解析为真实 obj_token，解决 91402 NOTEXIST
4. **资源操作**：create_bitable / create_table / create_field / batch_create_records / search_records / delete_record / get_record
5. **文档操作**：create_doc / append_doc_blocks
6. **权限管理**：share_with_user / transfer_owner（转移所有权失败降级为分享）

**关键设计**：
- JSON 手动序列化（`ensure_ascii=False`），发送原始 UTF-8 中文，避免飞书解析异常
- 所有方法先 `resolve_app_token`，防御 wiki node_token 问题
- `verify_bitable_access()` 在 onboarding 后验证 token 有效性

### 2.5 collector.py — 社招岗位采集器

> **注意**：校招用户的岗位采集已中心化到 `company_crawler.py` → `job_db.py`。`collector.py` 主要服务于社招用户的独立搜索。

**可插拔搜索提供者**：
- `TavilySearchProvider`（默认，有免费额度）
- `SerpApiSearchProvider`（Google 搜索）
- 通过环境变量 `TAVILY_API_KEY` / `SERPAPI_KEY` 自动选择

**采集流程**：
1. `_build_queries()` 根据用户 `direction_keywords` + `role` 构建搜索词（限 25 条）
   - 通用方向关键词搜索
   - 角色专项搜索（校招→校招/管培/应届，社招→社招；实习关键词已移除）
   - **拓展源1 微信公众号**：`site:mp.weixin.qq.com` + 重点公众号账号名精确搜索
   - **拓展源2 公司招聘官网**：`site:{公司招聘域名}` + 公司名+校招/社招关键词
   - **拓展源3 社区渠道**：`site:{社区域名}` + 内推关键词
2. 对每个搜索词调用搜索 API，获取结果列表
3. 初筛：标题需包含用户方向关键词或通用招聘词
4. `fetch_jd_by_source()` 根据 URL 来源选择抓取策略：
   - 微信公众号 → `fetch_wechat_article()`（提取标题/公众号/发布时间/正文）
   - 社区渠道 → `fetch_community_content()`（提取帖子正文）
   - 公司招聘官网 → `fetch_company_career_sitemap()` 辅助 + 通用抓取
   - 其他 → `fetch_jd()` 通用 BS4 解析
5. 提取公司（支持【公司名】格式）、地点、薪资、发布日期（支持微信"发布时间:"格式）
6. 去重 URL，限制返回数量

### 2.6 campus_companies.py — 校招公司来源库

**职责**：维护 2024-2026 年实际发过校招公告的企业清单，作为中心化采集的公司来源。

**规模**：488 家校招企业，覆盖 16 个行业（互联网、金融、快消、咨询、制造业等）。

**每家公司字段**：
| 字段 | 说明 |
|------|------|
| `name` | 公司名 |
| `type` | 公司类型：国央企 / 民企 / 外企 |
| `difficulty` | 申请难度：最激烈 / 激烈 / 普通 / 轻松 |
| `industry` | 所属行业 |
| `career_domain` | 官方招聘官网域名（如 `jobs.bytedance.com`，从 config 自动匹配） |
| `wechat_account` | 官方招聘公众号名称（如"字节跳动招聘"） |
| `last_announcement_url` | 历史公告链接（参考今年发布位置） |
| `last_announcement_date` | 历史公告日期（参考今年可能发布时间） |
| `has_2027_announcement` | 是否已发 2027 届公告（决定是否还需每日扫描） |

**公司库构成**：
- **基础盘**：2024-2026 发过校招的公司（大概率延续）
- **增量补充**：核心公众号/高校 CDC 发现的今年新招聘公司

### 2.7 company_crawler.py — 校招中心化采集器

**职责**：遍历公司来源库，搜索并抓取 2027 届校招公告，经 AI 检视后写入总数据库。

**采集策略**：
| 阶段 | 策略 |
|------|------|
| 首次初始化 | 遍历所有公司来源（可分批），找到已发的 2027 公告入库 |
| 之后每日 | 只扫描 `has_2027_announcement=False` 的公司，检查是否新发公告 |
| 已发公告公司 | 不重复扫描（除非公告关闭后可能补录，低频复查） |
| 新公司发现 | 每日扫核心求职公众号 + 高校 CDC，发现清单外公司 → AI 校验 → 补入公司库 + 总数据库 |

**核心方法**：
- `run_initial_crawl()` — 首次全量采集（遍历全部 488 家公司）
- `run_daily_crawl()` — 每日增量采集（只扫未发公告公司）
- `_build_company_queries()` — 构建 `site:{career_domain}` + `site:mp.weixin.qq.com` 查询
- `_process_announcement()` — 抓取 JD → AI 检视 → 生成摘要 → 入库

**采集方式**：不直接爬网站（反爬），用 Tavily `site:` 限定搜索（已验证可行）。

### 2.8 job_db.py — 校招总数据库（SQLite）

**职责**：集中存储 2027 届校招岗位，所有校招用户共享同一份数据源。

**存储路径**：`{DATA_DIR}/jobs.db`

**jobs 表结构**：
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK | 自增主键 |
| `company` | TEXT | 公司名 |
| `job_title` | TEXT | 岗位标题 |
| `cohort` | TEXT | 届数（固定 2027） |
| `source` | TEXT | 来源：公司官网 / 官方公众号 / 求职公众号 / 高校CDC |
| `jd_url` | TEXT | 公告链接 |
| `jd_summary` | TEXT | JD AI 摘要 |
| `industry` | TEXT | 行业 |
| `company_type` | TEXT | 公司类型：国央企 / 民企 / 外企 |
| `difficulty` | TEXT | 申请难度 |
| `deadline` | TEXT | 投递截止日期 |
| `publish_time` | TEXT | 发布时间 |
| `status` | TEXT | 在招 / 已关闭 |
| `crawl_time` | TEXT | 入库时间 |
| `ai_verified` | INTEGER | AI 检视是否通过（0/1） |
| `dedup_hash` | TEXT UNIQUE | 去重哈希（公司+标题归一化） |

**核心方法**：
- `init_db()` — 初始化表结构
- `insert_job()` / `batch_insert_jobs()` — 插入岗位（去重 hash 唯一约束）
- `get_active_jobs()` — 查询所有在招岗位
- `get_jobs_by_company()` — 按公司查询
- `mark_closed()` — 标记岗位已关闭
- `get_stats()` — 统计信息（总岗位数、在招数、已验证数）

**去重机制**：`dedup_hash = md5(公司 + 标题归一化)[:16]`，数据库层 UNIQUE 约束保证不重复。

### 2.9 user_matcher.py — 校招用户匹配器

**职责**：从总数据库中为校招用户筛选匹配岗位。

**两阶段匹配**：
1. **规则预筛**（过滤 ~70% 不相关）：
   - 行业匹配（用户目标行业）
   - 公司类型匹配（campus_company_types）
   - 专业关键词匹配（方向关键词）
2. **AI 评分**：复用 `scorer.score_job()`，输出相关性/难度/推荐度/简评/建议

**每公司限制**：最多 5 个岗位，避免单一公司刷屏。

**核心方法**：
- `match_jobs_for_user(user)` — 返回匹配岗位列表
- `_rule_filter()` — 规则预筛
- `_score_and_rank()` — AI 评分排序
- `_limit_per_company()` — 每公司最多 5 条

### 2.10 scorer.py — 评分引擎

**评分维度**（满分约 110）：

| 维度 | 分值 | 依据 |
|------|------|------|
| 方向匹配 | 10/25/40 | 是否命中用户目标方向 |
| 平台/公司 | 10/20 | 是否目标公司 |
| 经验匹配 | 5/10/12/15 | JD 经验要求 vs 用户年限 |
| 技能匹配 | 0-15 | 用户技能在 JD 中命中数 |
| 学历匹配 | 3/5/7/8/10 | JD 学历要求 vs 用户学历 |
| 行业匹配 | 0/5/10 | 是否目标行业 |

**难度评分**：基于经验要求、学历要求、平台层级、证书要求综合计算。

**综合推荐度**：
- ≥70 → 优先申请
- ≥50 → 可申请
- ≥30 → 观望
- <30 → 跳过

**去重 hash**：`md5(公司|标题|地点|JD链接)[:16]`

### 2.11 onboarding.py — 用户 Onboarding

**关键设计**：
- `_onboarding_lock = threading.Lock()` 防止并发回调创建多个多维表格
- 双重检查：加锁后再次确认用户不存在
- 创建后立即 `verify_bitable_access()` 验证
- 校招用户额外创建「管培生项目」表
- 失败时记录日志，不崩溃

### 2.12 daily_runner.py — 每日任务执行器

**流程**：采集/匹配 → 评分 → 去重写入 → 复查归档 → 生成日报 → 飞书卡片推送 → 截止提醒 → 投递跟踪

**校招 vs 社招分流**：
- **校招用户** (`role=campus`)：`user_matcher.match_jobs_for_user()` 从总数据库匹配
- **社招用户** (`role=social`)：`collector.collect()` 独立搜索

**关键设计**：
- `_ensure_table_fields()` 自动为存量用户补建缺失字段（行业/公司类型/难度等）
- `UserRunLock` 用户级文件锁防止即时采集与定时任务并发
- 管培岗位写入独立「管培生项目」表
- 飞书写入失败不阻塞推送；WxPusher 推送失败不影响数据
- 单用户失败不影响其他用户

### 2.13 callback_server.py — 回调服务

**端点**：
- `POST /feishu/callback` — 飞书事件回调（已实现 verification_token 校验）
- `GET /health` — 健康检查
- `GET /onboarding` — 客户自助配置页面
- `GET/POST /api/profile` — 获取/保存用户求职偏好（保存后后台触发即时采集）
- `POST /api/parse-resume` — LLM 简历解析
- `POST /api/optimize-keywords` — AI 优化方向关键词
- `POST /api/bind-wxpusher` — WxPusher 绑定（可选，兼容旧用户）

**安全加固**：
- 请求体大小限制 1MB
- 超时设置 10s
- malformed JSON 返回 400
- 飞书回调 verification_token 校验（配置后生效）

### 2.14 main.py — 调度入口

**命令**：
- `python main.py daily` — 为所有活跃用户执行每日任务（失败时管理员告警）
- `python main.py single <user_id>` — 为单个用户执行（测试用）
- `python main.py migrate-tokens` — 迁移存量用户 wiki token
- `python main.py weekly-ranking` — 每周校招投递热度榜

## 3. 数据流向

```
┌──────────────────────┐
│ 公司来源库 + 公众号CDC │
│ campus_companies.py  │
└──────────┬───────────┘
           │ 中心化采集(company_crawler)
           ▼
┌──────────────────────┐
│  总数据库 jobs.db     │◄──── AI 检视(新增时)
│  (2027届校招岗位)     │
└──────────┬───────────┘
           │ 校招用户匹配(user_matcher)
           │ 规则预筛 + AI评分 + 每公司≤5
           ▼
┌──────────────────────┐     ┌──────────────────┐
│  飞书多维表格(用户)    │────▶│  飞书文档(日报)    │
│  岗位库+管培表         │     │                  │
└──────────────────────┘     └──────────────────┘

社招用户: collector 独立搜索 → 评分 → 写入飞书表
```
