# 03 - 接口规范与配置说明

## 1. 环境变量配置

所有敏感信息通过环境变量注入，不硬编码。配置文件：`.env`

### 1.1 必填配置

| 变量 | 说明 | 示例 |
|------|------|------|
| `FEISHU_APP_ID` | 飞书商店应用 App ID | `cli_xxxxxxxx` |
| `FEISHU_APP_SECRET` | 飞书商店应用 App Secret | `xxxxxxxx` |
| `DEEPSEEK_API_KEY` | DeepSeek API Key | `sk-xxxxxxxx` |
| `DATA_DIR` | 数据存储目录 | `/workspace/job_assistant/data` |

### 1.2 可选配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `FEISHU_ENCRYPT_KEY` | 空 | 飞书事件加密密钥（MVP 可不填） |
| `FEISHU_VERIFICATION_TOKEN` | 空 | 飞书事件验证 Token |
| `WXPUSHER_APP_TOKEN` | 空 | WxPusher 应用 Token（微信推送，可选） |
| `ADMIN_WXPUSHER_UID` | 空 | 管理员 WxPusher UID（失败告警） |
| `SERVICE_BASE_URL` | `https://zhaopin-helper.xyz` | 服务域名 |
| `DAILY_JOBS_PER_USER` | `60` | 每用户每日采集上限 |
| `FEISHU_RETRY` | `3` | 飞书 API 重试次数 |
| `FEISHU_API_INTERVAL` | `0.2` | 飞书 API 调用间隔（秒） |

### 1.3 .env 示例

```bash
# 飞书应用
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=xxxxxxxx

# LLM
DEEPSEEK_API_KEY=sk-xxxxxxxx

# 数据目录
DATA_DIR=/workspace/job_assistant/data

# 微信推送(可选)
WXPUSHER_APP_TOKEN=AT_xxxxxxxx
ADMIN_WXPUSHER_UID=UID_xxxxxxxx
```

## 2. 飞书开放平台配置

### 2.1 创建商店应用

1. 访问 https://open.feishu.cn 创建企业自建应用
2. 权限配置：
   - `bitable:app` — 多维表格读写
   - `docx:document` — 文档创建
   - `drive:drive` — 云空间权限（分享+转所有权）
3. 事件订阅 → 配置请求地址（公网 HTTPS）
   - 订阅事件：`app_open`（应用被打开）、`app_install`（应用被安装）
4. 发布版本 → 申请商店上架（或测试企业安装）
5. 获取 App ID + App Secret

### 2.2 飞书 API 封装（feishu_client.py）

核心方法：

| 方法 | 说明 |
|------|------|
| `create_base(name)` | 创建多维表格 |
| `create_table(base_token, name, fields)` | 创建数据表 |
| `batch_create_records(base_token, table_id, records)` | 批量写入记录 |
| `search_records(base_token, table_id, filter, fields)` | 筛选查询记录 |
| `delete_record(base_token, table_id, record_id)` | 删除记录 |
| `create_doc(title)` | 创建飞书文档 |
| `append_doc_blocks(doc_id, blocks)` | 追加文档内容 |
| `share_with_user(doc_id, type, open_id)` | 分享文档给用户 |
| `transfer_owner(token, type, open_id)` | 转所有权给用户 |
| `send_message(open_id, text)` | 发送纯文本消息 |
| `send_card_message(open_id, card)` | 发送交互卡片 |

## 3. DeepSeek LLM API

### 3.1 模型

| 模型 | 用途 |
|------|------|
| `deepseek-chat` | 简历解析、JD 分析、岗位拆分 |
| `deepseek-vl` | 图片 OCR（公告图片识别） |

### 3.2 LLM 功能模块（llm_client.py）

| 方法 | 说明 | Prompt |
|------|------|--------|
| `parse_resume(resume_text)` | 简历结构化解析 | HR 角色扮演，提取 15 个维度 |
| `analyze_jd(jd_text, title, profile)` | JD 深度分析 | 生成摘要 + 申请建议 |
| `quality_screen_jobs(jobs, profile)` | AI 质量筛选 | 过滤低质量岗位 |
| `parse_announcement_jobs_enhanced(text, images)` | 公告拆分岗位 | 提取 25+ 维度 |

### 3.3 简历解析 Prompt 要点

- 角色：10 年经验资深 HR
- 输出：严格 JSON
- 提取维度：school/degree/major/core_skills/direction_keywords/target_cities/target_industries/certificates/summary/highlights
- `direction_keywords` 最关键：每个方向 5-8 个搜索关键词

### 3.4 岗位拆分 Prompt 要点

- 输入：公告正文文字 + 图片 OCR 结果
- 输出：岗位数组，每个岗位 25+ 字段
- 核心字段：job_category/hard_skills/major_required/min_education/city/certifications

## 4. 内部 API（callback_server.py）

用户配置页面通过 HTTP API 与后端交互。

### 4.1 POST /api/profile — 保存用户画像

**请求体**：
```json
{
  "user_id": "u_xxx",
  "profile": {
    "school": "清华大学",
    "degree": "硕士",
    "major": "计算机科学与技术",
    "graduation_year": "2027",
    "core_skills": ["Python", "SQL", "机器学习"],
    "direction_keywords": {
      "算法工程师": ["算法", "机器学习", "深度学习", "NLP"]
    },
    "target_companies": ["字节跳动", "腾讯"],
    "target_industries": ["互联网"],
    "target_cities": ["北京", "上海"],
    "target_certificates": ["CET6"],
    "preferred_company_types": ["民企", "外企"],
    "preferred_difficulties": ["最激烈", "较为激烈"],
    "preferred_locations": ["北京", "上海"]
  }
}
```

**响应**：
```json
{"code": 0, "msg": "ok"}
```

### 4.2 POST /api/parse-resume — 简历解析

**请求体**：`multipart/form-data`，字段 `file` 为简历文件

**响应**：
```json
{
  "code": 0,
  "profile": { ...解析后的 UserProfile... }
}
```

### 4.3 POST /feishu/callback — 飞书事件回调

接收飞书 `app_open` / `app_install` 事件，触发 onboarding 流程。

## 5. 命令行接口

### 5.1 main.py — 调度入口

```bash
python3 main.py daily              # 执行所有活跃用户的每日任务
python3 main.py sync               # 仅执行数据同步(飞书+分析)
python3 main.py single <user_id>   # 为单个用户执行(测试用)
python3 main.py weekly-ranking     # 每周校招投递热度榜
```

### 5.2 fetch_announcements.py — 阶段一抓取

```bash
python3 fetch_announcements.py --workers 5 --limit 1000
```

### 5.3 analyze_announcements.py / analyze_daemon.py — 阶段二分析

```bash
python3 analyze_announcements.py   # 一次性分析全部已抓取记录
python3 analyze_daemon.py          # 守护模式,持续消费新记录
```

### 5.4 run_parallel.py — 两阶段并行

```bash
python3 run_parallel.py            # 同时启动抓取+分析
```

### 5.5 monitor_panel.py — 监控面板

```bash
python3 monitor_panel.py           # 启动 Web 监控面板 (端口 8765)
```

## 6. 数据库操作 API（job_db.py）

### 6.1 announcements 表

| 方法 | 说明 |
|------|------|
| `insert_announcement(ann)` | 插入一条公告链接 |
| `batch_insert_announcements(anns)` | 批量插入 |
| `get_unanalyzed_announcements(limit)` | 获取待分析公告 |
| `update_announcement_analysis(dedup_hash, **fields)` | 更新分析状态 |
| `get_announcement_stats()` | 获取公告统计 |

### 6.2 jobs 表

| 方法 | 说明 |
|------|------|
| `insert_job(job)` | 插入一个具体岗位 |
| `get_all_active_jobs()` | 获取所有在招岗位 |
| `get_jobs_by_grade(grade)` | 按届数获取岗位 |
| `get_stats()` | 获取岗位统计 |

### 6.3 companies 表

| 方法 | 说明 |
|------|------|
| `upsert_company(name, **fields)` | 更新或插入公司 |
