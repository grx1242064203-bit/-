# 端到端测试用例 — 招聘情报助手

> 测试范围：从用户收到配置链接 → 上传简历 → 确认配置 → 飞书表格创建 → 岗位匹配写入 → 每日更新
> 不测：XHS 店铺自动发货（订单号自动生成+链接自动推送）

---

## 一、测试目标

1. 验证 `web_setup.py` 配置页完整链路（订单验证 → 简历解析 → 确认配置 → 飞书建表）
2. 验证岗位匹配逻辑（放宽限制后：推荐度≥"推荐"的岗位全部提供，不限每公司个数）
3. 验证每日更新机制（去重 + 新增 + 归档关闭）
4. 验证飞书推送（卡片 + 日报文档）

---

## 二、测试环境

| 项 | 值 |
|----|----|
| 服务器 | 47.250.216.165（阿里云轻量，2C896M） |
| 代码路径 | /opt/job_assistant/ |
| 配置页地址 | http://47.250.216.165/setup?order_id=test_e2e_001 |
| 数据管线 | full_pipeline 运行中（拆岗） |
| 岗位库 | 9256 条（持续增长） |

---

## 三、前置条件

1. 飞书应用权限已配置：`bitable:app`、`docx:document`、`drive:drive`
2. `.env` 中 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `DEEPSEEK_API_KEY` 已配置
3. `data/valid_orders.json` 为空（开发模式接受任意订单号）或已添加 `test_e2e_001`
4. 测试简历文本准备好（用于验证简历解析）

---

## 四、匹配策略调整（本次测试生效）

| 参数 | 当前值 | 测试调整值 | 说明 |
|------|--------|-----------|------|
| `min_score` | 30 | **55** | 只保留"推荐"及以上（≥55分） |
| `max_per_company` | 5 | **不限制** | 去掉每公司5个上限 |

调整位置：`daily_runner.py` 中 `match_jobs_for_user()` 调用处 + `user_matcher.py` 默认值

## 五、测试用例

### TC1: 配置页面访问

| 项 | 内容 |
|----|------|
| 前置 | web_setup 服务已启动，Nginx 路由 /setup → 5000端口 |
| 操作 | 浏览器打开 http://47.250.216.165/setup?order_id=test_e2e_001 |
| 预期 | ① 页面正常加载 ② 订单号自动填充 ③ 显示"第一步：验证订单" |
| 验证点 | HTTP 200，页面包含"校招岗位雷达"标题 |

### TC2: 订单验证

| 项 | 内容 |
|----|------|
| 操作 | 点击"验证订单"按钮 |
| 预期 | ① 验证通过 ② 自动进入"第二步：上传简历" |
| 验证点 | 无报错，step-resume 卡片显示 |

### TC3: 简历上传与 AI 解析

| 项 | 内容 |
|----|------|
| 操作 | 粘贴测试简历文本 → 点击"AI 解析简历" |
| 预期 | ① LLM 返回解析结果 ② 学校/学历/专业/毕业年份自动填充 ③ 目标方向自动填充 |
| 验证点 | 解析出的 school/major/degree/graduation_year 非空且合理 |
| 降级 | 若解析失败，手动填写配置，继续后续测试 |

### TC4: 确认配置 → 创建飞书表格

| 项 | 内容 |
|----|------|
| 操作 | 确认/调整配置 → 点击"生成我的岗位库" |
| 预期 | ① 创建用户 `xhs_test_e2e_001` ② 创建飞书多维表格（岗位库+已关闭+管培） ③ 返回分享链接 ④ users.json 中新增该用户 |
| 验证点 | `data/users.json` 含 `xhs_test_e2e_001`，且 `feishu_base_token` 非空；飞书表格可通过链接打开 |

### TC5: 一次性岗位匹配（核心）

| 项 | 内容 |
|----|------|
| 操作 | 执行 `python main.py single xhs_test_e2e_001` |
| 预期 | ① 匹配到岗位（推荐度≥"推荐"）② 写入用户飞书表格 ③ 生成日报文档 ④ 飞书卡片推送（若配置了 open_id） |
| 验证点 | 飞书表格中有新岗位记录；日报文档 URL 非空；所有写入岗位的"综合推荐度"为"推荐"或"强烈推荐" |
| 放宽验证 | 同一公司岗位数可 >5（验证 max_per_company 限制已去掉） |

### TC6: 每日更新（去重 + 新增 + 归档）

| 项 | 内容 |
|----|------|
| 操作 | 再次执行 `python main.py single xhs_test_e2e_001` |
| 预期 | ① 已写入的岗位不重复写入（去重生效）② 若有新岗位则新增 ③ 已关闭岗位归档到"已关闭岗位"表 |
| 验证点 | 第二次执行后，飞书主表记录数 = 第一次记录数 + 新增数（无重复）；hash_store 中有对应 hash |

### TC7: 飞书卡片推送

| 项 | 内容 |
|----|------|
| 前置 | 测试用户配置了 `feishu_open_id` |
| 操作 | 执行 `main.py single` |
| 预期 | 收到飞书卡片，含：当日新增数、TOP3 推荐、岗位库链接、日报链接 |
| 验证点 | 飞书消息卡片正常渲染，按钮可点击跳转 |

---

## 六、风险与回滚

| 风险 | 应对 |
|------|------|
| 飞书建表失败 | 检查 FEISHU 权限配置，重试 |
| 简历解析质量差 | 手动填写配置，不影响后续测试 |
| 匹配岗位数过多（飞书写入慢） | 观察写入耗时，必要时恢复 max_per_company 限制 |
| 污染生产数据 | 测试用户用独立 order_id，测试后可删除 `xhs_test_e2e_001` 用户及对应飞书表格 |
| 匹配策略调整影响生产 | 测试完成后确认是否保留新策略，或恢复原参数 |

---

## 七、测试后清理

1. 删除测试用户：从 `users.json` 移除 `xhs_test_e2e_001`
2. 删除测试用户的飞书多维表格（手动或 API）
3. 删除 `data/hashes/xhs_test_e2e_001.json`
4. 确认匹配策略调整是否保留为生产配置
