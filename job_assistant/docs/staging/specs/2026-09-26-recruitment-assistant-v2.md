## 1. WxPusher 推送策略调整

### 背景
用户反馈 WxPusher 未收到微信推送。经核查截图与服务状态：WxPusher API 仍可调用，但**微信公众号通道已被微信官方关闭**，消息只能送达 WxPusher App/小程序会话，无法直达用户微信。

### 决策
- **主推送渠道 = 飞书**（用户已安装飞书应用，触达率 100%）
- **WxPusher 降级为可选辅助通道**（保留代码，仅当用户主动绑定时使用，文档说明其限制）
- **取消 onboarding 流程中的微信绑定强制步骤**，改为可选

### 变更点
- `onboarding_page.html`: 微信绑定步骤改为可选，不阻塞完成
- `daily_runner.py`: 飞书消息增强为主要通知（TOP3 摘要 + 表格链接）
- `config.py`: `WXPUSHER_APP_TOKEN` 保留但标注为可选

## 2. LLM 简历解析（P0）

### 决策
- **LLM 提供商**: DeepSeek（性价比高、中文支持强、API 兼容 OpenAI 格式）
- **API Key 配置**: 环境变量 `DEEPSEEK_API_KEY`（运营方统一配置，用户无需提供）
- **解析方式**: 用户上传简历文本/粘贴 → 调用 DeepSeek → 结构化提取为 UserProfile 字段

### 提取字段（专业 HR 视角）
1. **基本信息**: 姓名、学历、学校、专业、毕业年份
2. **工作/实习经历**: 公司、岗位、起止时间、核心职责、量化成果
3. **技能**: 硬技能（工具/语言/框架）、软技能
4. **证书**: CFA/CPA/法考/PMP 等
5. **求职意向**: 目标岗位方向、目标城市、目标行业
6. **经验年限**: 自动计算

### Prompt 设计原则
- 角色扮演: "你是一位有 10 年经验的资深 HR，请从以下简历中提取结构化信息"
- 输出格式: 严格 JSON，无额外文本
- 容错: 缺失字段返回空字符串/空数组，不编造

### 文件
- 新建 `llm_client.py`: `LLMClient` 类，封装 DeepSeek 调用 + 简历解析 prompt
- `models.py`: `UserProfile` 新增 `resume_text`（原始简历文本，留档）、`graduation_year`
- `callback_server.py`: 新增 `/api/parse-resume` 端点

### 决策

## 5. 飞书推送增强（P0）

### 决策
飞书消息从纯文本升级为**交互卡片**，包含：
- 标题: "{专业}招聘日报 {日期}"
- 概览: 新增 N 条 / 关闭 M 条 / 优先申请 K 条
- **TOP3 岗位摘要**: 公司 · 岗位 | 地点 | 相关性 | 简评（前 60 字）
- **直达链接**: 岗位数据库表 / 已关闭岗位表 / 完整日报文档
- 底部: "明天 9:00 继续推送"

### 变更点
- `feishu_client.py`: 新增 `send_card_message()` 方法（msg_type=interactive）
- `daily_runner.py`: 日报推送改用卡片，包含 TOP3 + 表格链接

## 6. 校招截止提醒 + 投递跟踪（P1）

### 截止提醒
- `JOB_FIELDS` 新增 `投递截止日期`（datetime 字段）
- `collector.py`: 从 JD 提取截止日期（正则 + LLM 辅助）
- `daily_runner.py`: 每日检查主表中截止日期在 3 天内的岗位，飞书提醒

### 投递跟踪
- `JOB_FIELDS` 已有 `申请状态`（未投递/已投递/面试中/Offer/拒绝）
- 新增 `投递日期`（datetime）
- 用户在多维表格中标记"已投递"后，系统每日复查该岗位：
  - 若岗位关闭 → 通知用户"你投递的 {公司} {岗位} 已关闭"
  - 若岗位仍在招 → 不打扰
- 状态变更通过飞书消息通知
