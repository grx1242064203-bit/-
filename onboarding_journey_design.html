Offer搭子 Onboarding 旅程设计

新方案（V4 简化版）下的用户旅程梳理：下载桌面端 → 注册/登录 → 上传简历 → 看岗位 → 投递追踪
方案：飞书侧只保留总表回写，桌面端功能不变 日期：2026-10-05 评估口径：现状盘点 + 缺口标注
核心结论：5 步旅程中,前 2 步（注册/登录）后端 + 前端框架已完整就绪,后 3 步（上传简历/看岗位/投递追踪）功能已实现但缺少新用户引导串联。最大缺口是"登录后未上传简历时 Jobs 页面是空的,没有引导用户先上传简历",导致新用户首次进入易困惑。补一个 WelcomeWizard 引导组件即可串联整条旅程。

STEP 4 · 看岗位

  • 岗位匹配适配器：job_matcher_adapter.py，构建用户画像 → 调 UserMatcher.match_jobs_for_user → 评分 → 推荐等级

三、关键缺口与建议（不实施,供后续规划）

缺口 1：登录后缺少 WelcomeWizard 引导组件（建议优先级 P1）
症状：新用户登录后直接跳 /(Jobs),Jobs 因无简历画像返回空数据,用户看到空页面困惑。
第一性原理：求职工具的核心价值依赖用户画像,新用户必须先上传简历才能解锁岗位推荐。应有引导组件串联"上传简历 → 解析 → 看岗位"。
建议方案：在 App.tsx 路由层加一个 OnboardingGuard,检测 resumeStore.activeResume 为空时跳 /welcome 引导页,引导页含三步:① 介绍产品 → ② 上传简历(复用 ResumeUploader) → ③ 跳 Jobs 看推荐。完成后跳回原路径。
改动范围：新增 job_workbench/src/pages/Welcome.tsx + job_workbench/src/components/OnboardingGuard.tsx,在 App.tsx 包裹受保护路由。后端无需改动。
缺口 2：Jobs 页面缺少"无简历"空状态 CTA（建议优先级 P2）
症状：即使用户绕过 WelcomeWizard 直接访问 Jobs,看到的是空列表,无明确"请先上传简历"提示。
建议方案：在 Jobs 页面加 EmptyState 组件,检测 resumeStore.activeResume 为空时显示"上传简历解锁岗位推荐"卡片 + 跳转按钮。
缺口 3：投递追踪缺少"截止日期提醒"看护逻辑（建议优先级 P1,新方案评估报告已标注）
症状：原 DailyRunner._check_deadline_reminders 与 _check_applied_jobs 已随 DailyRunner 类删除,用户失去"截止日期≤3天提醒"和"已投递岗位关闭通知"。
用户决定："其他 P1 和 P2 风险我会再考虑,先不动"——本缺口按用户决定暂不实施,在此仅作记录。
建议方案（待用户决定后实施）：把看护逻辑提取为独立函数 check_deadlines() / check_applied_status(),改为读 job_api 的 applications 表(不读飞书用户表),结果写入 notifications 表供桌面端拉取 + Tauri 系统通知。

六、用户旅程验证清单

新方案下完整 onboarding 旅程的端到端验证步骤(供测试用):

  1. 下载安装：make build-app 产出安装包 → 安装到测试机
  2. 首次启动：应用打开 → 应跳 /login(因未登录,AuthGuard 拦截)
  3. 注册新账号：点"注册" → 填邮箱密码 → 收验证码 → 验证 → 跳回 /login
  4. 登录：输入邮箱密码 → 跳 /(Jobs) — 此处当前是缺口,理想应跳 /welcome 引导上传简历
  5. 上传简历：当前路径:点侧边栏 Resume → 上传 PDF → 等待 parse-resume-file 返回 → 画像入库
  6. 看推荐岗位：跳回 Jobs → 看到 job_matcher_adapter 评分后的岗位列表
  7. 投递追踪：点岗位"标记投递" → 跳 Applications → KanbanBoard 拖到"已投递"
  8. 邮件/日程：Email 页绑定 IMAP → 收到面试邮件 → 转 Schedules 日程
  9. 飞书总表(只读视图)：用户可访问 https://www.feishu.cn/base/J8qtbBvPdatotysARtbc2XcinDJ 浏览全部岗位(每日 8:00 后更新)
