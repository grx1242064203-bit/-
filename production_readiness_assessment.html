5. 残留风险 (建议处理,不阻塞上线)

优先级问题建议
P1 POST /llm/parse-resume 在 DeepSeek 调用失败时返回 200 + 空 keywords,前端无法判断失败 routers/llm.py 调用失败应抛 503,而不是返回空 ParsedProfile
P1 登录限流 5/min 太严,正常使用都会触发 调到 10/min 或 20/min,或加邮箱维度而非 IP 维度
P2 applications.user_id 表 schema 仍是 INTEGER,但存 UUID 字符串(SQLite 动态类型兼容,长期存在隐患) 迁移脚本把 applications.user_id 列类型改为 TEXT(需重建表)
P2 无 GET /llm/quota 端点,前端无法预知剩余配额 加 quota 查询端点,前端在上传前查剩余次数
P2 用户公司尽调端点共享 LLM 配额,逻辑上不合理 拆分为 parse_quota 和 research_quota 两个计数器
